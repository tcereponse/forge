5. Gestion des fallbacks CPU
5.1. Modes de fonctionnement
gpuMode: "auto" :

Utilise TensorRT-LLM si GPU disponible et stable.

Bascule automatiquement sur CPU si :

pas de GPU,

out-of-memory GPU,

erreur TensorRT-LLM.

gpuMode: "gpu-only" :

Échec explicite si GPU indisponible (utile pour bench et tests).

gpuMode: "cpu-only" :

Force l’utilisation CPU, même si GPU présent (debug, compat).

gpuMode: "remote" :

Appel vers un backend distant (cloud) si configuré.

5.2. Stratégie de fallback
Avant chaque requête IA :

GET /v1/capabilities.

Décision de mode (gpu ou cpu).

En cas d’erreur GPU (OOME, runtime):

Log l’événement.

Rejoue la requête en mode CPU.

Remonte à l’UI un indicateur « GPU failure, CPU fallback ».

6. Workflow de Génération de Code
6.1. Vue globale
Input utilisateur : description, features, packs, stack.

Construction du prompt & PRD (GPU).

Génération du code (GPU).

Post-traitement (GPU/CPU).

Build & validation (CPU).

Export & preview.

6.2. Étapes détaillées
Étape 1 – Création du projet
UI → core : project.create (stockage en base/local).

core appelle POST /v1/prd/generate avec prompt, features, packs.

Service GPU produit :

10 docs PRD,

métadonnées (latence, device, mode).

Étape 2 – Génération de code
core assemble :

arsenal PRD,

stack chosen,

packs actifs.

core appelle POST /v1/code/generate.

Service GPU renvoie :

fichiers React, config, scripts, templates APK.

core écrit les fichiers dans le workspace projet.

Étape 3 – Post-traitement
validation scanne :

imports manquants,

dépendances non référencées,

corruption \n vs n.

core appelle POST /v1/code/repair avec les fichiers et les issues détectées.

Service IA corrige :

ajoute fichiers manquants,

ajoute dépendances,

crée stubs si nécessaire.

Étape 4 – Build & Aperçu
build-runner :

npm install,

npm run build,

collecte logs.

UI reçoit les événements :

build.progress,

build.success / build.failure.

Onglet « Aperçu » charge dist/ dans un iframe.

Étape 5 – Évolution de projet
UI → core : project.evolve (nouvelles features/packs).

core appelle POST /v1/prd/generate avec contexte projet + évolution.

core appelle POST /v1/code/generate avec code existant + instructions d’évolution.

Service IA génère les nouvelles pages / composants, en respectant l’existant.
